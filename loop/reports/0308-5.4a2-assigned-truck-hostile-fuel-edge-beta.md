# 0308 — 5.4a2 assigned plow truck: hostile fuel / edge values in the saved truck record (G4, lane A) — main @ 9ac3345 (tracklayer.js?v=255)
Scenario: tools/playtest/scenarios/x5_assign_hostile_beta.mjs (copy of the x5_plowdriver_mine_truck_beta setup; per case it sets the assigned truck's `fuel` or its blade `cond`, snows the road, runs the contract clock 1.5 h, reads the record, Staff + Plow cards and notifications). Asserts as committed fail on findings 1-2. No page errors, no exception in any case. Reload at the end keeps finite values.

Setup: fresh save, 90k cash, Freight licence, two plow trucks, a driver hired on the Gamvik road with truck v1 assigned, noon, no weather, traffic off. Cases: fuel null / "lots" / -40 / 1e9 / NaN; edge null / "x" / -3 / 50 (edge `cond` is 0-100, not 0-1).

## Findings
1. [BUG, low: needs a damaged save] A fuel that is a string ("lots") or NaN is not caught on the way out: the driver SETS OUT and the notification reads "In your Nordtrekk Brøyt 4x2, NaN L in the tank." The run then burns it to 0 and the driver comes home with "tank is empty". Null and -40 are caught correctly ("the ... tank is empty", driver stays home).
   Suggested fix: coerce the record once at the top of the set-out check (`const f = Number.isFinite(+T.fuel) ? Math.max(0, +T.fuel) : 0`) and use it in the `T.fuel <= ...` test and the note (tlx-plow.js ~1076, 1089).
2. [POLISH] Null and negative fuel are left as null / -40 in the truck record after the driver refuses (huge fuel is left alone too: 1e9 burns normally, fine). Only the note and card read clean, so nothing shows; the next reader of `r.fuel` (the truck's own gauge, tlx-vehicles) owns that, see 0301. Normalising on load would fix both.
3. [OK] Edge null / string loads as a fresh edge (100) and wears normally (96.8 after the run); -3 reads 0 and the driver stays home with "cutting edge is worn ragged"; 50 wears to 46.8. Staff and Plow cards never show undefined/NaN/null/Infinity in any case.
