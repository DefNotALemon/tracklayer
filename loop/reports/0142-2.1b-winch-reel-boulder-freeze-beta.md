# 0142 — 2.1b winch REEL under load, boulder anchor (v197) beta — main @ 4207682
Scenarios (new): `x2_winchreel_break.mjs` (all winches, mild/deep bog, doubled line, touch REEL), `x2_winchweak_break.mjs` (weak anchor, over-capacity drag; boulder case surfaced the bug), `x2_winchboulder_break.mjs` (the repro, asserts renders keep coming). Nothing new landed since 0141, so I took 2.1b's untested part from 0130 (REEL under load). Numbers only; one still-free pass.

## Findings
1. [BLOCKER] Hooking the winch to a BOULDER and reeling freezes the screen for good. `selfReel` (tracklayer.js ~14767) calls `wobble(a, ...)` on whatever the anchor is, and `wobble` pushes it into `wobbling`; `updWobble` -> `setTree` -> `trunkOf(o)` reads `(o.pine ? pineCells : birchCells)[o.cell].tm` and a boulder has no `cell`, so it throws `Cannot read properties of undefined (reading 'tm')` inside `frame()` at the `updWobble(dt)` line, which comes BEFORE `renderer.render`. The entry is never removed (the throw skips the splice), so every later frame throws too. Measured with a render counter (`x2_winchboulder_break.mjs`): tree anchor 67 renders in 2.5 s while reeling; boulder anchor **0 renders in 2.5 s while reeling and 0 in the 1.5 s after release**, `wobbling.length` stuck at 1, 49+ page errors in that run (327 in the longer one). The sim keeps running (sled still gets pulled free, HUD/tablet frozen too since `updGameHud`/render are after it), but the player sees a frozen picture until they reload. Boulders are the strongest anchors (cap 42,000 vs birch 4,655-7,000), so they are exactly what the toast "Nothing in reach looks good enough: try a bigger tree" / "The boulder N m out will hold" steers you to. Other callers guard with `o.tree !== undefined` (lines 2893, 3254, 3257, 16371); `selfReel` (14767) and the rescue tie (15257, `WN.tie`) do not. Suggested fix: `if (a.tree !== undefined && ...) wobble(...)` at 14767 and 15257, and make `wobble()` itself return when `o.tree === undefined` so no future caller can do it. Also worth try/catch-free hardening: `updWobble` should drop an entry whose `trunkOf` is missing.
2. [POLISH] Reel works as designed otherwise. Birch cap 7,002 (hand winch 7,000), mild bog (need 2,280): hand 7.2 game s to free, electric 4.1 s, heavy 3.5 s; deep bog (need 4,395): hand 11.1 s, heavy 4.8 s single, 8.1 s doubled (doubling costs 0.55x speed, so it is slower when you weren't stalling; fine, the toast only offers it when stalling). Tension bar, fuel (hand 0, electric 0.059 L, heavy 0.067-0.167 L) and "Free!" toast all fine. But the hand winch never stalls on any real bog (max need 4,395 < 7,000), so the stall / "double the line" / line-parts path is unreachable in normal play except with a heavy tow; not exercised (my drag setup via `TOW.mass` did not push `need` over cap because need only uses TOW when not bogged and the tow was ignored: need 961).
3. [Verified] Touch: REEL button appears when hooked, a held pointer pulls (moved 0 -> 1.21 m in 2.5 s), release stops it. No NaN on any run.
4. [Observation] Hand winch run burned 0.021 L of fuel in 7 s although it has no fuel use: that is idle burn of the parked bogged sled, small.
5. Not tested: winch with the pickup active (`winchDef()` null while `VEH.cur`; `VEHICLES` isn't reachable from the scenario scope, needs `TLX` api), pad REEL, the rescue-tie wobble (same bug likely on a tied boulder at 15257).

## Ideas
- Pull the "is this wobble-able" check into `wobble()` so boulders, rocks and any future anchor kind (poles, signs) are safe.
