## Findings
1. [BUG, med] Road snow depth under the pickup does not follow the stretch's snow value, and 50% is the worst case. Same spot on fv888 (stretch set with `TLXR.setSnow`, rider parked 2.5 game s, depth read each 3 s, steady): snow 0 → 0.22 m, **snow 0.5 → 0.59 m**, snow 1.0 → 0.14 m. Pickup holding W for 14 game s: 39 / 54 m at 0 and 1.0, **0.1 m at 0.5** (stuck, vmax 0, repeated twice, so not order-dependent). So a half-drifted road is a wall while a fully drifted ("snowed in", Map blue) one is easier than the plowed one. Report 0141 #2 saw 0.31 m at 0.54 when snow built up gradually; here it is an instant set, so suspect `replow` heaping snow when `Y.k` is mid-range and the depth catch-up not matching (`ROADS.plow*(1-q)`). Suggest sampling depth at q = 0, .25, .5, .75, 1 after `replow` and making it monotone (more drift = deeper, up to the surrounding pack).
2. [Verified] Planted junk roads state loads in every variant (`r` null, array, short/long/string `s`, `p` as string or 1e9, `h` string/negative/1e9/far future, roads key missing entirely): stretch counts always re-fit (13/7/5/15/11), roads ready, no NaN, no tickErr.
3. [POLISH] Clock running backwards (GS.hour -30, e.g. a debug jump) just rebases `st.h`, no snow lost, no NaN; fills again from the next tick (0.65 → 0.98 in 2 storm hours). Fine.
4. [POLISH] `snowStep` has no guard for `st.h` NaN; JSON cannot store NaN so a real save cannot trigger it, but a `typeof st.h === "number" && isFinite` check in `snowInit` costs nothing.
