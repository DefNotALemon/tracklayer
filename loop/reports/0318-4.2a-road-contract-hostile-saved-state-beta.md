## Findings
1. [POLISH] `conTidy` keeps `due` keys that are not stretches of the road. Planted `due {"999":[5,1],"-1":[1e12,1]}` on a clear Dyfjord road: they survive load and `step()`, and `quitCost("dyfjord")` is true, so HAND BACK would be a warning on a road with nothing on it ("handing the road back now is a warning"). Only reachable from a damaged save. Fix: in conTidy drop keys that are not integers in `0..r.seg.length-1` (conRec already prunes unknown roads; do the same for stretches).
2. [POLISH] `conBan` is only checked for finite: `gamvik: 1e15` is a permanent lock on signing that road, and a ban for a road id that no longer exists is kept. Fix: clamp to now + 7 days (the max real ban) and drop unknown ids.
3. [POLISH, unexplained] One case (`dueGarbage`: strikes 1 plus due `"0":[null,1] "1":"no" "999":[5,1] "2":[NaN,0] "3":[-4,1] "-1":[1e12,1]`) loaded as strikes 2, clean false. The probe with only the out-of-range keys did not strike, and a valid stretch with a 1e12 h clock struck once (right: it is very late). I did not isolate which entry the second strike came from; possibly "3":[-4→0,1] then a due check, possibly the late stretch counted twice. Low priority, hostile-only.
