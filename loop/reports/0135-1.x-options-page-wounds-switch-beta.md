# 0135 — 1.x Options page (the "Poachers on the fell" switch): pad, reload, old saves, off while bleeding (G4 beta) — main @ 712c644 (v193)
Scenarios: tools/playtest/scenarios/x1_options_wounds_break.mjs (13 ok, 1 FAIL = finding 1, page errors none), x1_options_touch.mjs (4 taps, all flip)   Shot: ~/.hermes/cache/scratch/tlloop/reports/0135.jpg

Nothing new landed since 0134, so I took milestone 1's Options page, which only has x1_save (a fake test option) behind it. The one real option is the wounds switch.

## Findings
1. [POLISH] Switching "Poachers on the fell" off while you are bleeding does not stop the bleeding. Two wounds open far from every site (2.9 km), option off, 8 s of game time: still open, bar still up, health 97.9 -> 89.1. The hint says "Off = never", and a player who turns it off mid-bleed expects the hazard gone. Suggest the option's `change(false)` clears open wounds (or the tick does when `!TLX.on("wounds")`).
2. [POLISH] The option's hint says "bandage it fast (the bandage control)" without naming the button, while every other hint goes through `btn()`. The row is registered before input exists, so the text is static; build the hint from `api.btn("bandage")` when the page opens (the HUD and toast already do). Same page footer: "Esc closes ... M opens the map on your tablet" is the line from the still, keyboard letters shown to a pad/touch player (footer does already add the pad line).
3. [POLISH] The Options row is the last control on the page: 14 d-pad-down presses from the first control to reach it on a pad (it works, see below). Fine for one row; will get long once more options register. Consider a jump (e.g. an "Options" entry reachable by stick up from the bottom, wraparound).

## Verified (no bug found)
- Default: row reads `Poachers on the fell: on`, section visible, pad focus ring clearly visible (shot).
- Pad: d-pad down reaches the row, A flips it off and on, B closes Settings.
- Touch: four taps flip the row on/off/on/off, each a single click (no double fire). (In the main scenario a tap right after several reloads did not flip it once; I could not reproduce it in a clean boot, so I put it down to the harness, not the game.)
- Save: `x.opt.wounds === false` is written; after reload the option is off, `exposed()` false, the row reads off.
- Old save with no `x`: option defaults on. An `x.opt.wounds: "no"` (junk string) reads as ON — harmless.
- Fresh game at the depot: a forced `hit()` is patched up the same frame (depot heals), so test wounds away from sites.
