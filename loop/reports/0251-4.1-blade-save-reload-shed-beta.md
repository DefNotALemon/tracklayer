# 0251 — 4.1 blade state through save/reload, shed round trip, corrupt state (beta, tester 1)

Build: origin/main aa1a8f9 (v251, tlx-plow v13). Scenario: `tools/playtest/scenarios/x4_blade_save_break.mjs` (exit 0, page errors none).
Chosen because 4.1a/4.1b blade state had no save/reload break test; 4.2b1 (0250) skipped, under two hours old with no new code.

## What passed
- Blade slewed left, edge at 55, opened 7, 1234 m cut: all four come back after a save + reload (throw `l`, cond 55).
- Unfit puts one blade in the shed; refit empties it and keeps the edge (55).
- A plow state full of garbage (ghost uid, null blade, null shed entry, string grit, null con) loads with no page error; `tidy()` and the hint run clean.
- A save with no `x` at all loads with zero blades.

## Findings
1. POLISH — a refit resets the slew to `r`: set left, unfit, fit again and the throw reads `r` (edge kept at 55). A player who took the blade off for the season and put it back has to re-slew. Suggest keeping `throw` on the shed entry the way `cond` is kept (or note it as intended).
2. POLISH — my first probe read `blades[uid].wear`; the field is `cond` (100 = new). Not a game bug, only a note that the old `wear` name appears nowhere in state, so any scenario or doc that mentions it is stale.

No BLOCKER or BUG.
