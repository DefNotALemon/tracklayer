## Findings
No BLOCKER.
1. BUG (low) — a partly cleared drive forgets its progress on reload. Cut 70% of Ole-type drive, `save()`, reload, then plowed the remaining 40% (from 60% on): no pay, drive still snowed in (cash 55800 unchanged). `DV.marks` is memory only and `drvApply` clears it on init. The player who quits mid-clearing must redo the whole drive. Suggest saving the marks (a bitmask string per drive in `drv[key]`) or at least saying so; a note in the card would do for a first fix.
2. OK — blade UP the full length of a snowed-in drive: no pay, no progress, `n` stays 0. Walker on foot with the blade "down" beside the truck: nothing paid.
3. OK — old save with no `drv/drvOff/drvH/drvPaid/drvN` keys: `tidy` rebuilds them, step/app/Jobs render, no NaN/undefined.
4. OK — all eight taken on and stormed: one Jobs row "Plow out 8 driveways", 8 Map pins (= due count).
5. OK — polar night: `payMul` 1.5, a $42 drive paid $63 at full pay. A second pickup with no blade: Jobs row shows but is not auto-tracked and the riding hint stays empty.
6. POLISH — headless frame time with eight drives snowed in read 62 ms/frame; I have no baseline run without drives, so this is only a flag for the builder (headless is slow anyway). Worth one A/B run.
7. Test note (not a game bug): setting `FOOT.on = true` then false leaves `TLXV.state().cur` null (no truck current), so the next `bladeOf(cur)` is null; scenarios must `TLXV.swapTo(uid)` after toggling FOOT directly.
